Engine Source Documentation

Overview

The Engine source folder contains the core functionality of the game engine, implemented in the D programming language, and the user interface, implemented in Python. This documentation provides an overview of the main components and their responsibilities.

Python TKinter Interface

Overview

The Python interface provides the game editor, as well as manages interaction with the game engine and game runner through a Tkinter-based GUI.

Installation

To install the required dependencies, run the following command from the Engine directory:

python -m pip install -r interface/requirements.txt

Running the Interface

To start the interface, run the following command from the Engine directory:

python interface/main_menu.py

Interface Components

  • main_menu.py

    The main entry point for the interface, providing access to:

    • Play Game
    • Level Selection
    • Level Editor
    • Options Menu

  • options_menu.py

    Manages game settings including:

    • Music volume control
    • Background music selection
    • Special effects toggle (not yet implemented)

  • level_chooser.py

    Provides an interface to:

    • Preview user-created levels
    • Play user-created levels

  • edit_menu.py

    Level editor to interface with:

    • Game object placement tools
    • Level saving

  • toolbar.py

    Handles the possible editing tools for the level editor.

  • sprite_loader.py

    Handles sprite loading and management for the interface.

Level Editor and JSON Format

The level editor saves levels in a JSON format that serves as the bridge between the Python interface and the D engine. The JSON file contains:

  • level_name: The name of the level
  • grid: A 32x32 grid representing the level layout
  • sprites: Information about the sprites used in the level
  • sprite_animations: Animation data for sprites

Grid Elements:

  • W: Wall
  • M: Mouse (player, starting point)
  • C: Cat (antagonist)
  • G: Goal (portal / hole in the wall)
  • P: Pellets (cheese)
  • (space): Empty cell

Interface-Engine Integration

The Python interface and D engine work together through the following workflow:

  1. User creates/edits a level in the Python interface
  2. Level is saved as a JSON file in the levels/ directory
  3. When playing a level, the D engine is launched with the JSON file as an argument: dub -- Assets/level1.json Assets/options.json
  4. The D engine reads the JSON file to construct the level and initialize game objects

The level editor performs validation before saving to ensure the level is playable, checking for:

  • Presence of exactly one player (M)
  • Presence of exactly one goal (G)
  • Valid grid dimensions (32x32)

Core Engine Files

  • app.d

    The entry point of the application. Initializes the game with command-line arguments for level and options files.

    Usage: dub -- Assets/level1.json Assets/options.json

  • gameapplication.d

    Manages the main game loop and application lifecycle. Key responsibilities include:

    • Window and renderer initialization
    • SDL and SDL_TTF initialization
    • Audio system setup
    • Scene management
    • Frame timing and FPS control
    • Input handling
    • Rendering pipeline

  • component.d

    Implements the component-based architecture for game objects. Key features include:

    • GameObject class for entity management
    • IComponent interface for component system
    • SpriteComponent for rendering and animation
    • ScriptComponent for custom behavior
    • AnimatedTexture for sprite animation support

  • gamescene.d

    Implements the main game scene, handling game-specific logic and rendering.

  • menuscene.d

    Manages the menu interface and user interactions.

  • scene.d

    Base class for all scenes, providing common functionality for scene management.

  • audiomanager.d

    Handles audio playback and management, including:

    • Music loading and playback
    • Volume control
    • Audio system initialization

  • resourcemanager.d

    Manages game resources such as textures and fonts, providing:

    • Resource loading and caching
    • Texture management
    • Resource cleanup

  • sdl_abstraction.d

    Provides abstraction layer for SDL functionality, simplifying SDL interactions.

  • textrenderer.d

    Handles text rendering and font management.

Architecture

The engine follows a component-based architecture with the following key patterns:

  • Component System: Game objects are composed of components that provide specific functionality
  • Scene Management: Scenes organize game content and manage their own update/render cycles
  • Resource Management: Centralized resource handling with caching and cleanup
  • Event System: SDL-based input handling and event propagation

Dependencies

  • SDL2 (via bindbc.sdl)
  • SDL2_mixer (via bindbc.sdl.mixer)
  • SDL2_ttf (via bindbc.sdl.ttf)
  • Standard D library (Phobos)
