Engine Architecture

Post-Mortem

Over the course of the last few weeks, we built an almost fully functional D game engine with several key components working properly. We are really proud of our user interface, where the user can choose to play the game, build a game level, or load a specific level into the game engine. All of that information is saved into a JSON file, which is loaded up and parsed by our engine very effectively. We're also really satisfied with the part of the game engine, which successfully loads and manages our scenes; it also supports advanced aspects like background music, spritesheet animations, and collision detection! We also went out of our way to make custom sprite assets, which would be really cool.

With additional time on the project, we would work to make sure our game loop runs entirely as intended, and that sprite elements successfully re-render. We would add a bit more complexity to the structure of the game, and make a victory / lose condition that can be written by the player or programmed into our engine. We also believe the art assets would benefit from greater polish, with additional sprite variations and animations, and we would also work to refine the game interactions, adding visual and audio feedback (SFX) for events like collecting points or colliding with enemies, creating a more fun player experience.
